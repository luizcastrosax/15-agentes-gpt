## PREÂMBULO

O DeGold OS é um Sistema Operacional Institucional de Inteligência para Mercados Financeiros.

Seu propósito não é prever mercados.

Seu propósito é transformar dados confiáveis em decisões probabilísticas de alta qualidade através de engenharia, governança, evidência estatística e preservação permanente de capital.

Toda evolução do projeto deverá respeitar esta Constituição.

Caso exista conflito entre qualquer documento e esta Constituição, prevalecerá esta Constituição.

---

## ARTIGO I — MISSÃO

O DeGold OS existe para:

* preservar capital;
* produzir vantagem estatística sustentável;
* reduzir decisões emocionais;
* transformar fluxo institucional em informação operacional;
* padronizar decisões;
* construir um sistema auditável, explicável e escalável.

---

## ARTIGO II — VISÃO

Construir a principal plataforma institucional de decisão para traders discricionários e sistemáticos, mantendo compatibilidade entre diferentes plataformas e tecnologias.

---

## ARTIGO III — VALORES PERMANENTES

São valores permanentes do DeGold OS:

* Integridade dos dados.
* Honestidade estatística.
* Explicabilidade.
* Robustez.
* Simplicidade.
* Auditoria.
* Transparência.
* Disciplina.
* Preservação de capital.
* Evolução contínua baseada em evidências.

Esses valores não poderão ser removidos.

---

## ARTIGO IV — LEIS FUNDAMENTAIS

**Lei 1**
Mercado é probabilidade. Nunca certeza.

**Lei 2**
Liquidez precede preço. Preço é consequência.

**Lei 3**
Fluxo institucional possui prioridade sobre indicadores derivados apenas do preço.

**Lei 4**
Capital sempre possui prioridade sobre retorno.

**Lei 5**
Nenhuma operação é obrigatória. Não operar também é decisão institucional.

**Lei 6**
Uma vantagem estatística é superior a uma opinião.

**Lei 7**
Toda decisão deve possuir contexto.

**Lei 8**
Nenhuma feature será considerada válida apenas porque "parece funcionar".

**Lei 9**
Toda evolução deverá ser mensurável.

**Lei 10**
Todo algoritmo deverá ser auditável.

---

## ARTIGO V — DEFINIÇÃO OFICIAL DE EDGE

Edge é uma vantagem estatística demonstrada por evidência reproduzível.

Para existir Edge é obrigatório existir:

* hipótese;
* causalidade plausível;
* evidência;
* repetibilidade;
* expectativa positiva;
* robustez.

Sem esses elementos não existe Edge. Existe apenas hipótese.

---

## ARTIGO VI — CICLO DE VIDA DAS FEATURES

Toda feature obrigatoriamente percorre:

```
Ideia → Hipótese → Especificação → Implementação → Validação
→ Backtest → Out Of Sample → Walk Forward → Promoção
→ Monitoramento → Descontinuação
```

Nenhuma etapa poderá ser ignorada.

---

## ARTIGO VII — PROMOÇÃO

Uma feature somente poderá entrar em produção quando possuir:

* consumidor definido;
* documentação;
* testes;
* métricas;
* rollback;
* compatibilidade.

---

## ARTIGO VIII — REMOÇÃO

Uma feature deverá ser removida quando:

* não produzir valor;
* aumentar complexidade;
* duplicar funcionalidades;
* reduzir robustez;
* perder consumidor;
* apresentar deriva permanente.

---

## ARTIGO IX — IA

A Inteligência Artificial **poderá:**

* sugerir melhorias;
* detectar drift;
* recomendar pesos;
* explicar decisões;
* gerar documentação;
* auxiliar auditorias.

A Inteligência Artificial **não poderá:**

* alterar princípios constitucionais;
* criar Edge automaticamente;
* modificar produção sem aprovação;
* alterar parâmetros críticos autonomamente.

---

## ARTIGO X — DADOS

Dados são classificados como:

| Classificação | Descrição |
|---|---|
| `VALID` | Pode originar decisões críticas |
| `INVALID` | Não pode originar decisões críticas |
| `UNKNOWN` | Não pode originar decisões críticas |
| `NOT_AVAILABLE` | Não pode originar decisões críticas |

Dados não classificados como `VALID` não poderão originar decisões críticas.

---

Todo código deverá ser:

* modular;
* performático;
* explicável;
* versionado;
* documentado;
* auditável;
* testável;
* reproduzível.

---

## ARTIGO XII — VERSIONAMENTO

Toda versão deverá possuir:

* objetivo;
* escopo;
* mudanças;
* compatibilidade;

## ARTIGO XIII — COMPATIBILIDADE

O núcleo conceitual do DeGold OS deverá permanecer consistente entre:

* GPT;
* API;
* NinjaTrader;
* TradingView;
* BlackArrow;
* Python;
* Massive;
* Feature Store;
* Historical Edge;
* demais componentes oficiais.

---

## ARTIGO XIV — GOVERNANÇA

Toda alteração estrutural deverá possuir:

* justificativa;
* impacto;
* avaliação de risco;
* plano de migração;
* auditoria.

---

## ARTIGO XV — ROBUSTEZ

Robustez possui prioridade superior à sofisticação.

Complexidade somente será aceita quando produzir benefício comprovado.

---

## ARTIGO XVI — PRESERVAÇÃO DE CAPITAL

Nenhuma melhoria poderá aumentar expectativa de retorno sacrificando de forma desproporcional o controle de risco.

---

## ARTIGO XVII — FILOSOFIA DE DESENVOLVIMENTO

A ordem oficial de construção do DeGold OS é:

```
Dados Confiáveis → Hipóteses → Modelos → Features → Engines
→ Edge → Execução → Produto → Escala → IA Adaptativa
```

Essa ordem é obrigatória.

---

## ARTIGO XVIII — IDENTIDADE

O DeGold OS **não é:**

* um indicador;
* um robô;
* um setup isolado;
* uma coleção de scripts.

O DeGold OS **é** uma plataforma institucional de inteligência para tomada de decisão.

---

## ARTIGO XIX — IMUTABILIDADE

Os princípios desta Constituição são considerados congelados (Frozen).

Alterações somente poderão ocorrer mediante:

* nova versão constitucional;
* documentação completa;
* justificativa técnica;
* registro permanente no histórico do projeto.

---

## ARTIGO XX — CLÁUSULA FINAL

Toda evolução futura deverá fortalecer:

* consistência;
* governança;
* robustez;
* vantagem estatística;
* preservação de capital;
* qualidade das decisões.

Nenhuma atualização poderá comprometer esses princípios em troca de conveniência ou velocidade.
